## What this app now is

A real screen recorder. The parked work at
`_shared/parked/rectap-screen-recorder-wip.patch` was applied: a local Expo
module `modules/screen-recorder`, an iOS **ReplayKit Broadcast Upload
Extension** generated by `plugins/withBroadcastExtension.js`, an Android
`MediaProjection` foreground service, and the screens and state machine that
drive them.

The central constraint, which no simplification survives: `RPScreenRecorder`
records **only the host app's own UI**. Whole-device capture on iOS requires the
broadcast extension plus an App Group, started by the user through Apple's own
`RPSystemBroadcastPickerView`. That is what is built here, and it is also why
most of the recording gates below cannot leave `UNKNOWN` on a simulator.

## Known UNKNOWNs

- Everything above marked ⬜, and in particular: **no recording has ever been
  made by this app.** The whole capture path — broadcast extension, App Group,
  AVAssetWriter, duration cap, library import — is unexercised code. It needs a
  physical iPhone and a physical Android device.
- The paywall's own "Restore purchase" button is silent when there is nothing to
  restore: `usePremiumStore.restore()` returns `'none'` and the screen shows
  neither an alert nor a line of text. Settings does show the alert. This is in
  template-owned code (`app/paywall.tsx`), so the fix belongs in
  `_shared`, not here.

## What a human has to do next, on hardware

1. Register the extension App ID `com.altixcode.rectap.broadcast` and the App
   Group `group.com.altixcode.rectap`, and enable the App Groups capability on
   both. A device build without this records into a container the app cannot
   read — and fails silently.
2. On a physical iPhone: tap Record, pick Rectap in Apple's sheet, tap Start
   Broadcast, leave the app, come back, stop. Then open the file from the
   Recordings screen **and from outside the app** (share it to Files and play
   it) — a recorder's only proof is a playable mp4 of the right length.
3. Let a free recording run past 3 minutes and confirm it stops on its own with
   a complete file, and that the app explains why.
4. Build and drive Android once: the MediaProjection consent dialog, the
   foreground-service notification, recording while another app is in front, and
   the same file check.
